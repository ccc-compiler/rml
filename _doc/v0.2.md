# RML v0.2 — rmlgo 專案管理工具

RML v0.2 新增 `rmlgo`（類似 cargo 的專案管理工具），用來協調 `rmlc`、`rustc`、`cargo` 的呼叫。

## rmlgo

`rmlgo` 是單檔程式 `rmlgo.rs`，負責管理 RML 專案結構、呼叫編譯器鏈，並整合 Rust 生態系（透過 cargo 進行最終建置與相依管理）。

### 建置

```bash
rustc -O rmlgo.rs -o rmlgo
```

### 指令

- `rmlgo new <name>`：建立新 RML 專案，包含 `src/main.rml`、`Rml.toml`、`Cargo.toml`、`.gitignore`
- `rmlgo init`：在目前目錄初始化 RML 專案（自動補足缺少的檔案）
- `rmlgo build`：編譯專案。流程：`rmlc src/main.rml --stdout` → `target/gen.rs` → `cargo build --release`
- `rmlgo run`：建置並執行已產生的 release 執行檔
- `rmlgo check`：僅型別與所有權檢查（呼叫 `rmlc` 驗證，不產生最終執行檔）
- `rmlgo clean`：清理 `target/` 與根目錄下同名 `.rml` 對應的中間 `.rs` 檔案
- `rmlgo help`：顯示說明

### 專案結構

`rmlgo new` 產生的結構：

```
<name>/
  ├── src/
  │   └── main.rml        # RML 入口程式
  ├── target/             # 產生檔案（gen.rs、release/debug）
  ├── Rml.toml            # RML 專案設定
  ├── Cargo.toml          # Rust 橋接設定（指向 target/gen.rs）
  └── .gitignore
```

`Cargo.toml` 將 `[lib]` 與 `[[bin]]` 路徑設定為 `target/gen.rs`，讓 `cargo` 負責最終的 Rust 編譯、優化與連結。這是 v0.2 將建置工作委派給 cargo 的設計：`rmlc` 負責 RML → Rust 的語言轉換，`rmlgo` 負責專案管理與工具鏈協調，`cargo` 負責 Rust 生態與建置。

### 設計原則

- **單一檔案工具鏈**：`rmlgo.rs` 單檔實作，與 `rmlc.rs` 一樣易於編譯與散佈
- **最小侵入**：沿用既有 `rmlc` CLI，不修改 v0.1 編譯器行為
- **自動化**：`build` 自動產生 `target/gen.rs` 並呼叫 `cargo build --release`
- **相容性**：能自動尋找 `rmlc`（優先 `./rmlc` 本地二進位）、入口 `.rml` 檔案（`src/main.rml` 或專案根目錄）

## 與 v0.1 的差異

- 新增 `rmlgo` 專案管理工具
- 支援標準化的 RML 專案結構（`src/`、`Rml.toml`、橋接 `Cargo.toml`）
- 建置流程整合 cargo（支援 release build、日後可擴充相依管理）
